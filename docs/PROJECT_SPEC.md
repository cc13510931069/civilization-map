# 《文明的地图 HD》产品规格

## 产品定位

iPad 横屏优先的互动学习应用，面向初高中生。通过地图探索、证据收集和 AI 引导的五步文明思考，帮助学生形成自己的文明解释能力，而非被动记忆知识点。

### 核心理念

《文明的地图 HD》**不是**一个打卡型学习 App，它是一款文明探索教育工具。

界面中的探索路径、章节解锁、地图节点等视觉隐喻，目的**不是**驱动"完成–奖励"循环，而是服务于更深层的认知转变：

**知识接受者 → 文明解释者**

学生使用这个 App 后，应该能对任意一个文明区域做出自己的解释——说出它在哪里、环境如何、谁在那里互动、历史如何变化、以及这一切意味着什么。

## 原书内容结构

所有文明探索内容必须严格依据《文明的地图》（张信刚）一书结构：

### 七个部分

1. **文明研究** — 方法论基础
2. **丝绸之路** — 东西文明交流的动脉
3. **大中亚的点与面** — 中亚地区的文明分布
4. **印度速写** — 印度文明扫描
5. **波斯文明圈** — 波斯文明的影响
6. **高加索巡礼** — 当前开发模板
7. **土耳其进行曲** — 土耳其文明

### 第 37–38 章

- **第37章** — 古丝绸之路综合探索
- **第38章** — 新丝绸之路现实连接

不得自行扩展成普通世界文明课程。

---

## 五个探索区域

每个文明区域在互动地图上围绕以下五个维度组织探索节点：

1. **国界观察站** — 文明的地理边界与战略位置
2. **山地探险区** — 地形如何塑造文明特征
3. **水系追踪区** — 河流、海域与文明的关系
4. **城市侦察区** — 核心城市与文化中心
5. **文明连接区** — 贸易路线与文化交流

---

## 精读营

阅读《文明的地图》各章节原文，标记并收集阅读证据。精读营是独立主入口，可以与地图证据和 Mission 闭环联动。

---

## 五步思考框架

所有区域通用：

| 步骤 | 问题 | 能力维度 |
|---|---|---|
| 1 | **在哪里？** | 位置与知识 |
| 2 | **有什么条件？** | 位置与知识 / 证据使用 |
| 3 | **谁在那里活动？** | 历史因果 |
| 4 | **发生了什么变化？** | 历史因果 |
| 5 | **我的解释是什么？** | 个人解释 |

---

## 证据系统

- **地图发现**：在世界地图或区域地图上点击发现点
- **阅读证据**：在精读营中选中文字并标注类型
- 地图证据或阅读证据**任一种即可**满足最终提交条件
- 所有证据自动聚合到 `missionEvidenceProvider`

### 证据统计

`countMissionEvidenceSources()` 是唯一定义地图/阅读证据分类的纯函数。

## Veggie（菜狗）角色

**中文名**：菜狗  
**英文名**：Veggie  
**定位**：AI 文明探索导师、文明探索伙伴

不是答案机器人。Veggie 的行为优先：

- 提问
- 引导观察
- 引导寻找证据
- 建立因果关系
- 鼓励形成个人解释

### 单步辅导

针对五步中每一步的 AI 辅导：

- 学生提交单步答案
- Veggie 给出发现、加强、下一步思考
- 支持多次修订（`revisionNumber` 递增）
- 支持跳过和取消跳过

---

## 学习闭环

```
地图探索 → 发现证据 → 阅读补充 → 五步文明思考 → Veggie 辅助 → 形成文明解释 → 我的文明地图
```

## Mission 规则

### 提交阶段

| 阶段 | 说明 |
|---|---|
| draft | 初始草稿 |
| submittingInitial | 初步提交中 |
| initialFeedback | Veggie 初步反馈 |
| revisionReady | 修改后准备重新提交 |
| submittingFinal | 最终提交中 |
| completed | 最终评价完成 |
| failure | 服务异常 |

### 最终提交条件

1. 五步答案各自 trim 后至少 6 字符
2. 地图证据或阅读证据**任意一条**即可
3. 当前不处于提交中

### 工作流规则

- 草稿状态与正式快照隔离（`missionSubmissionProvider` 管理草稿，`missionResultSnapshotProvider` 管理正式快照）
- 只有正式提交成功后才写入快照
- 修改草稿但未再次提交时，快照保持旧版本
- MyMap 只读取 `missionResultSnapshotProvider`
- **首次合法正式提交生成版本 1**
- **`completed` 状态不能直接重复提交**
- **必须修改答案并调用 `markModified()`，进入 `revisionReady`**
- **`revisionReady` 成功提交生成下一版本**
- 每次成功提交，`submissionVersion` +1
- 快照记录版本号，MyMap 显示最新版本

### 单一规则来源

三处共同调用 `evaluateFinalSubmissionEligibility()`：

- `canSubmitFinalProvider`
- `finalSubmissionReadinessProvider`
- `submitFinal()`

## 评价维度

四项能力，每项 0–25 分：

| 维度 | 分值 | 说明 |
|---|---|---|
| 位置与知识 (locationScore) | 0–25 | 空间认知 |
| 证据使用 (evidenceScore) | 0–25 | 证据运用 |
| 因果与逻辑 (causalityScore) | 0–25 | 历史因果 |
| 个人解释 (explanationScore) | 0–25 | 个人观点 |

总分 0–100。

| 层 | 内容 |

## 高加索模板与 RegionModule 架构

高加索是未来所有区域模块的技术模板。

未来新增区域应当配置化复用 `RegionModule`：

```
RegionModule
├ 地图
├ 图层
├ 探索节点
├ 证据点
├ 阅读材料
├ 思考任务
├ AI 辅导
├ 评价体系
└ 我的文明地图成长
```

配置层与 Flutter 渲染层必须解耦。配置层不得保存 Widget、CustomPainter、BuildContext 或渲染工厂。渲染器通过稳定 ID 注册表查找：`rendererId → Widget/Painter 实现`。

目前尚未开始大规模 RegionModule 迁移。

## 技术与架构

| 项目 | 值 |
|---|---|
| Flutter | 3.44.6 stable |
| Dart | 3.12.2 |
| 状态管理 | Riverpod（flutter_riverpod） |
| 路由 | GoRouter / ShellRoute |
| 布局 | iPad 横屏优先 |
| 包管理 | Swift Package Manager（不强制 CocoaPods） |

### 架构原则

- 所有区域相关内容（模型、地图数据、探索进度）数据驱动，课程内容与 UI 逻辑解耦
- 按区域隔离，每个区域的数据独立，`regionId` 标识
- 地图绘制组件（CustomPainter）应可被 SVG 资源替换而不影响业务逻辑

### 状态管理

- 使用 Riverpod 管理全局状态（探索进度、章节解锁、用户偏好）
- 避免将业务状态混入 Widget 层级

### 开发纪律

- 修改前先完整阅读实现和现有测试
- 优先最小修复，避免大范围重构
- 不删除失败测试，不添加 `skip`，不降低断言标准
- 不使用 `dynamic`、`Object` 或 `cast` 掩盖类型问题
- 不使用 `sed`、Python `str.replace` 或正则批量修改 Dart 结构
- GoRouter 项目中不使用 `Navigator.pushNamed` 切换主栏目
- 类移动、模型统一或 Widget 结构修改后要冷启动模拟器验证

### 验证要求

每个阶段至少运行：

```bash
dart format .
flutter analyze
flutter test --reporter expanded
```

涉及 iPad UI 时还必须：

- 模拟器冷启动
- 人工点击、滚动和导航验收
- 检查红屏、RenderFlex overflow、ParentDataWidget 错误、状态丢失
- 不能只依赖 Widget 测试

## 辅助反馈规则

徽章（Badges）、经验值（Points / XP）、等级（Levels）可以存在，但必须满足以下条件：

1. **只能作为辅助反馈**，不能成为页面主导视觉元素
2. **必须关联能力成长**——例如"地理定位 Lv.3"比"总等级 Lv.5"更有意义
3. **不能驱动付费/营销转化**
4. **不能替代内在动机**——界面应优先让学习者感受到"我理解了"，而非"我升级了"

---

## 禁止设计

以下机制**不允许**作为核心成长驱动：

- ❌ **单纯连续签到** — 不设计每日签到、连续登录奖励
- ❌ **关卡数量作为主要成长指标** — 不把"完成了多少章"当作主要成就展示
- ❌ **星星收集作为核心奖励** — 不设计以收集星数/徽章数为目标的闭环
- ❌ **为解锁而完成任务** — 任务必须本身有思考价值，不能只是"做这个才能看下一个"的栅栏
